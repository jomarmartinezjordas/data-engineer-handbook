## P1 — Revenue & Bookings Daily  *(Investor‑facing)*

**Purpose**: Produce daily revenue, bookings, refunds, MRR/ARR and product‑line breakdowns used for CFO briefings and investor updates.  
**Upstream Inputs**: Payments (e.g., Stripe), Invoices (ERP/Accounting), CRM (opportunities/won), Refunds/RMAs, FX rates.  
**Orchestration**: Airflow DAG `rev_bookings_daily`; transforms in **dbt Core**; storage in BigQuery.  
**Primary/Secondary**: Ana Santos / Diego Reyes.  
**SLA**: T+1 07:00 PHT (SEV‑1 if ≥08:00).

**Health Checks**
- Source vs warehouse counts (D‑1) within ±0.5%.
- Payment vs invoice reconciliation by currency.
- dbt tests: `not_null`, `unique`, referential integrity on `invoice_id`, `payment_id`.

**Common Issues & Fixes**
- *Late webhooks/payments* → Re‑run incremental load for D‑1/D‑2; widen watermark 48h, document variance.  
- *Schema drift (payment fee fields)* → Pin schema in staging, ship hotfix model + backfill last 7 days.  
- *FX file missing* → Use prior day rate with flag `fx_is_stale=TRUE`, notify Finance channel.

**Backfill Procedure**
1. Tag window: `start_date`, `end_date` params in Airflow.  
2. Pause dependent marts; backfill staging → core → marts in order.  
3. Reconcile totals vs source exports; attach report to incident ticket.

**Escalation**
- If net revenue delta >1% post‑reprocess, **page CFO liaison** and **freeze dashboards** (read‑only banner) until resolved.

## P2 — AR Aging & Collections  *(Investor‑facing)*

**Purpose**: Produce AR aging buckets (0‑30/31‑60/61‑90/90+), dunning status, collections rate.  
**Inputs**: ERP invoices, payments, credit memos, write‑offs.  
**DAG**: `ar_aging_daily`; transforms in dbt.  
**Owners**: Ana / Diego.  
**SLA**: T+1 06:00 PHT; weekly cash view Mon 09:00 PHT.

**Checks**
- Invoice state transitions valid (issued→paid/voided).  
- Aging bucket sums = AR balance in ERP.  
- Overdue% trend guardrail (+/‑ 5pp WoW).

**Common Issues**
- *Partial payments not linked* → Re‑key join on `(invoice_id, payment_id, amount)`; rebuild materialized view.  
- *Backdated write‑off* → Trigger rolling 30‑day rebuild; tag affected invoices.  

**Collections Playbook**
- Auto‑post top 20 delinquent accounts to #collections with owner, amount, days overdue.  
- If ≥90+ bucket grows >10% WoW, page Finance ops for manual review.

## P3 — Acquisition & Activation Funnel

**Purpose**: Attribute traffic→lead→signup→qualified→activated across channels.  
**Inputs**: Ads APIs (Meta/Google), web events, CRM leads, product activation events.  
**DAG**: `growth_funnel_hourly` (raw) + `growth_funnel_daily` (modeled).  
**Owners**: Ben / Diego.  
**SLA**: Hourly raw; daily modeled by 06:30 PHT.

**Checks**
- Event‑to‑signup join rate within historical band.  
- Cost ingestion vs ad platform spend within ±1%.  
- UTM taxonomy validation (blocked if missing `utm_source`/`utm_campaign`).

**Common Issues**
- *API quota*/timeout → Exponential backoff; fall back to previous hour; mark partial.  
- *Attribution window change* → Parameterize lookback; regenerate last 14 days; notify stakeholders.

**Backfill**
- Rerun hourly loaders for window; then rebuild attribution models with frozen cost tables snapshot.

## P5 — LTV & Cohort Profitability  *(Investor‑facing)*

**Purpose**: Cohort LTV, payback period, LTV:CAC by channel/region, margin after variable costs.  
**Inputs**: P1 revenue, P3 spend & cohorts, COGS tables, refunds.  
**DAG**: `ltv_cohorts_weekly` (+ monthly).  
**Owners**: Ana / Cara.  
**SLA**: Weekly Mon 10:00; Month‑End M+3 18:00 PHT.

**Checks**
- Cohort counts lock vs P3; revenue accrual method documented.  
- LTV vs last run deltas ±1% unless spend changed.  
- Payback KPI recompute validated by Finance sampler notebook.

**Common Issues**
- *COGS delay* → Generate provisional LTV with `is_provisional=TRUE`; replace once COGS lands.  
- *Channel reclass* → Rebuild LTV from cohort start; attach change log.

## Incident Management

- **Severities**  
  - **SEV‑1:** Investor‑facing tables miss SLA or numbers inconsistent (freeze dashboards, executive comms).  
  - **SEV‑2:** Major freshness/quality issues impacting internal stakeholders.  
  - **SEV‑3:** Non‑critical task failures with easy workaround.

- **Runbook (All SEVs)**  
  1) Acknowledge alert (PagerDuty).  
  2) Post status in #data‑incidents with pipeline, SLA, ETA.  
  3) Diagnose (last green task, failing operator, logs).  
  4) Mitigate (retry, widen watermark, backfill).  
  5) RCA within 24h; add test/check; close ticket.

**Change Management**
- PRs require 1 reviewer (area lead) + smoke tests in staging.  
- Scheduled releases **10:30–16:30 PHT** Tue–Thu; freeze during Month‑End.  
- Version tags on critical marts with rollback SQL provided.
